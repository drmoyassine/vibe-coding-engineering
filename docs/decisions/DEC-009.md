context: >-
  VEF 0.1.0 exposed initialization, migration, repair, projection, strict validation, and health as several commands and
  flags. Although the mechanics were safe, adopters had to understand internal phases and repeatedly confused a clean
  doctor report, package acquisition, structural repair, adapter compatibility, and full enforcement.
decision: >-
  The public adoption lifecycle has two commands. `vef setup` acquires an explicit current CLI invocation, initializes
  or upgrades the repository, performs every mechanically safe repair, projects ledgers, validates strictly, deploys or
  reports CI enforcement, and finishes at the strongest state deterministic code can prove. `vef check` is the single
  strict read-only local and CI acceptance gate. `vef doctor` only explains blockers. Legacy lifecycle commands and
  flags remain callable but hidden for compatibility and framework maintenance.
rationale: >-
  Users think in terms of adopting, updating, and proving enforcement rather than migration engine phases. Two explicit
  intents remove flag composition, make upgrades repeatable through `@latest`, and preserve the semantic boundary: the
  CLI may repair structure but must stop before guessing product meaning. A pinned managed CI check turns successful
  setup into durable enforcement outside an agent session.
consequences: >-
  Positive — one command for every setup/upgrade state, one acceptance command everywhere, safer fresh-repository
  preflight, repeatable CI deployment, and compatibility for existing callers. Negative — maintainers still need hidden
  low-level commands for debugging and agent staging; non-GitHub CI requires adding the one emitted check command; setup
  cannot resolve semantic ambiguity without human or agent reconciliation.

# DEC-009 — Make setup and check the complete public adoption lifecycle

The normal path is deliberately memorable:

```text
npx vibe-engineering-framework@latest setup
npx vibe-engineering-framework@latest check
```

`--yes` is deliberately absent from the human workflow because it is an npm package-runner approval control, not part of VEF. Generated non-interactive CI may use it so installation cannot pause for input.

Setup is a deterministic lifecycle orchestrator, not an agent. It stops when project meaning is unresolved and points to reviewed reconciliation. Check proves only the implemented project-memory contract; optional adapter compatibility remains a separate reported dimension.
