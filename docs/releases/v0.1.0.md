# VEF 0.1.0 — release candidate

> Prepared launch copy. Publish it only after the npm `@latest` package and clean-directory registry flow have been verified.

## Short announcement

AI-assisted engineering has a memory problem. Vibe Engineering Framework keeps a project's vision, architecture, roadmap, tasks, decisions, and learnings in a Git-native typed model that humans and agents can both inspect—and that deterministic code can validate.

VEF 0.1.0 ships the Integrity Core, per-item Markdown storage, generated reading ledgers, deterministic graph queries, safe adoption tooling, and optional Claude Code adapters. It is early, operational, and dogfooded by its own repository.

## What is included

- Canonical Markdown/YAML records with stable IDs and typed relationships.
- Complete inverse-link, orphan, duplicate, cycle, schema, provenance, and projection validation.
- `vef init`, `vef doctor`, and non-destructive `vef doctor --fix` adoption flows.
- Read-only `list`, `show`, `refs`, `why`, `graph`, and `search` commands with JSON output.
- One-file-per-item canonical storage plus committed, generated ledgers for human reading.
- Optional agent adapters that remain consumer-owned and are never overwritten by doctor.
- Ubuntu and Windows release gates, including clean installation from the packed npm artifact.

## What is deliberately not included

- No claim that VEF replaces issue trackers or project-management tools.
- No general-purpose transactional `create` or `update` CLI yet.
- No hosted database or required proprietary agent memory.
- No shipped human-review UI yet; that work remains on the roadmap.

## Try it after registry publication

```bash
npx vibe-engineering-framework@latest init --name "My Project"
npx vibe-engineering-framework@latest doctor
npx vibe-engineering-framework@latest validate --strict
```

For an adopting repository that installs VEF as a development dependency:

```bash
npm install --save-dev vibe-engineering-framework
npx vef doctor
npx vef doctor --fix
```

## Invitation

The most useful early feedback is concrete: where the model fails to express real project intent, where adoption is confusing, where validation permits drift, or where a safe workflow requires too much agent-specific behavior. Open a GitHub Issue with a minimal example or propose a focused change.
