# Vibe Engineering Framework 0.2.0

VEF 0.2.0 makes the entire adoption lifecycle teachable as two commands.

## Adopt or update

```bash
npx vibe-engineering-framework@latest setup
```

Setup detects whether the repository is new, legacy, current, structurally repairable, or semantically blocked. It initializes or upgrades, performs every mechanically safe repair, projects the public ledgers, validates strictly, deploys or reports CI enforcement, and finishes at the strongest state deterministic code can prove.

## Prove enforcement

```bash
npx vibe-engineering-framework@latest check
```

The same strict read-only command runs locally and in CI. A pass means the canonical store, committed projections, schemas, typed relationships, inverse links, cycles, duplicate IDs, review state, and durable-memory catalogue satisfy VEF's implemented contract.

## Safety and compatibility

- Setup preflights fresh framework surfaces before writing.
- Semantic ambiguity stops structural repair; VEF does not invent product meaning.
- Existing agent adapters and custom CI workflows are preserved.
- GitHub enforcement is pinned to the setup version; other CI systems receive one portable command.
- `doctor` remains read-only troubleshooting.
- 0.1 lifecycle commands and flags remain callable but are hidden from normal help.

## Scope

This release simplifies adoption and enforcement. It does not add general-purpose transactional record writes or the planned human-review workspace.
