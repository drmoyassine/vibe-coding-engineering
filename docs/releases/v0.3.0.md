# Vibe Engineering Framework 0.3.0

VEF 0.3.0 makes deterministic code—not agents—the supported writer for structured project memory.

## Preview and apply

```bash
npx vef create task --from proposed-task.yml
npx vef update TASK-013 --from proposed-update.yml
```

Both commands preview the complete candidate by default. Explicit `--write --actor <id>` applies the candidate only
after schema, relationship, inverse-link, cycle, duplicate, catalogue, and projection validation passes. The engine
owns IDs when omitted, lifecycle dates, modification provenance, canonical references, inverse links, and ledgers.

## One writer for every adapter

The tasks, roadmap, decisions, and apply adapters now author semantic proposals and delegate structural work to the
same exported transaction API. They no longer carry independent canonical YAML or Markdown serializers. External
integrations can consume the executable schema through `vibe-engineering-framework/schema` and the transaction API
through `vibe-engineering-framework/transactions`.

## Recoverable on real developer filesystems

- Intent and hash-verified before/after content are journaled before the first project-file write.
- An interrupted journal blocks setup, check, and later mutations until explicit forward or rollback recovery.
- Stale-tolerant PID/host/timestamp leases serialize concurrent agents without depending on lock-file deletion.
- Windows, OneDrive, Dropbox, antivirus, and open-file interference use direct-write retries rather than rename-over-target assumptions.
- Cleanup failures are warnings after success; settled journal and lease debris cannot impersonate active work.

VEF does not claim database-level multi-file atomicity. It provides explicit, tested recovery from every target-write
boundary.

## Narrow deterministic repair

`vef update --authority frontmatter|heading` can reconcile one named title mismatch. It does not relax any unrelated
preflight failure or infer which semantic title is correct.

## Evidence

The release includes crash-boundary, concurrency, Windows busy-file, cleanup-debris, adapter, package-export, and
17-record authoring-replay tests. The replay proves engine conformance and first-pass structural validity; it is not
presented as an independent productivity claim.

The public adoption lifecycle remains:

```bash
npx vibe-engineering-framework@latest setup
npx vibe-engineering-framework@latest check
```

The planned lightweight human-review workspace is not part of this release.
