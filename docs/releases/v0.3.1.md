# Vibe Engineering Framework 0.3.1

VEF 0.3.1 hardens the public transaction writer after independent fault injection of 0.3.0.

## Safe writer-lease recovery

Malformed or incomplete files under `.vef/transactions/_leases/` no longer crash lease inspection and permanently block every write without diagnosis. `vef doctor` inventories active, malformed, quarantined, expired, dead, released, settled, and orphan-renewal families and prints the exact remedy.

After confirming no writer is active:

```bash
npx vef recover leases
```

Recovery preserves fresh possibly in-flight claims unless `--force` is explicitly confirmed. It writes an additive quarantine or settlement marker before best-effort cleanup, so a locked file or synchronized-folder resurrection cannot regain ownership. New writers boundedly sweep provably inactive debris; active writers are never swept.

## Authoring corrections

- A fresh roadmap created without an ID receives `ROADMAP-001`.
- A roadmap collection with one coherent numeric family continues that family; mixed or non-numeric families require an explicit ID.
- Vision records continue to require semantic slug IDs.
- `vef update <id> --authority frontmatter|heading` no longer requires an empty proposal file.
- Ordinary updates still require `--from`.
- `vef update --help` documents scalar, body, unset, and relationship grammar.
- `vef recover` is visible as a break-glass command while normal adoption remains only `setup` and `check`.

## Verification boundary

The release gate runs the full source suite and installs the exact packed artifact into an isolated consumer. That installed package must prove fresh setup/check, lease diagnosis and recovery, inactive-debris sweep, fresh and inferred roadmap allocation, authority-only repair, update grammar help, and visible recovery guidance.

VEF still does not claim database-level filesystem atomicity. It provides hash-verified explicit recovery, serialized writers, complete validated candidates, and durable evidence about interrupted state.
